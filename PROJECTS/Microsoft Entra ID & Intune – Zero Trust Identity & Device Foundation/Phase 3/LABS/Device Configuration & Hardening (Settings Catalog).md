# LAB 3.6 – Device Configuration & Hardening (Settings Catalog)

## Goal

The goal of this lab is to **harden Windows devices** by enforcing **security configuration baselines** using the **Settings Catalog** in Microsoft Intune.

This reduces the attack surface at the operating system level.

---

## Why This Matters

Even compliant devices can remain vulnerable if security settings are not enforced.

Without configuration hardening:
- Security depends on default OS behavior
- Misconfigurations remain undetected
- Attack surface remains unnecessarily large

Device configuration policies are essential for **defense in depth**.

---

## What Was Implemented

During this lab, the following configurations were applied using the Settings Catalog:

- Enforcement of security-related Windows settings
- Hardening of OS-level controls
- Alignment with Microsoft-recommended security practices
- Assignment of configuration profiles to managed Windows devices

These settings complement compliance and Conditional Access controls.

## Validation

The configuration hardening was validated by:

- Verifying policy deployment status in Intune
- Checking applied settings on the Windows device
- Confirming successful device sync and reporting
- Ensuring no conflicts with existing compliance policies

---

## Key Concepts Applied

- OS-level security hardening
- Configuration vs compliance distinction
- Defense in depth
- Centralized endpoint configuration

---

## Result

At the end of this lab:

- Windows devices follow a consistent security baseline
- OS-level risks are reduced
- Endpoint configuration is standardized
- The overall device security posture is improved

This lab strengthens **endpoint security beyond basic compliance**.
